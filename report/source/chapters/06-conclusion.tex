\section{Rebuilding the Report and Running the Live Demo}
To regenerate all figures from the Phase 8 audited evidence and recompile \path{report/main.pdf} from the workspace root (\texttt{EW\_redo}):
\begin{verbatim}
py -3.13 report/build_figures.py
Push-Location report
latexmk -pdf -interaction=nonstopmode -halt-on-error -outdir=build main.tex
Copy-Item build/main.pdf main.pdf -Force
Pop-Location
\end{verbatim}

For the classroom presentation, we organize our live demonstration around three short storylines:
\begin{enumerate}
\item \textbf{Part 1 --- Compound Key Order \& Sort Elimination (UC1):} Show why a single-column index on \texttt{OWNER = 'SYS'} regresses in MongoDB ($462.8$\,ms vs.\ $241.0$\,ms scan), how the 3-key compound index drops \texttt{U1a} to $2.34$\,ms ($9.46$\,ms in SQL), why omitting \texttt{OWNER} (\texttt{U1c}) prevents a seek, and how \texttt{U1d} eliminates the \texttt{Sort} operator.
\item \textbf{Part 2 --- Filtered/Partial Index Savings vs.\ Outside-Subset Fallback (UC2) \& Covering Lookup Elimination (UC3):} Show the $>99.5\%$ index storage reduction on \texttt{TEMPORARY = 'Y'} vs.\ full scan fallback on \texttt{'N'}, followed by \texttt{RID Lookup} / \texttt{FETCH} elimination on UC3 medium ranges.
\item \textbf{Part 3 --- Full-Text Search Semantics \& Write Trade-Offs (UC4) and Columnstore Compression (UC5):} Contrast multi-second \texttt{LIKE} scans with $14$--$23$\,ms \texttt{CONTAINS} and $1.8$--$6.4$\,ms \texttt{\$text} queries, compare SQL Server's $5.80$\,s async visibility lag against MongoDB's $-95.3\%$ sync insert drop, and inspect SQL Server's $23.15:1$ columnstore compression and post-write \texttt{OPEN} delta rowgroup.
\end{enumerate}
